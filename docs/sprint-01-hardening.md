# Sprint 01 hardening

Reviewed 2026-11-07 on `codex/sprint-01-foundation`. Sprint 02 and merging remain excluded.

## Findings and changes

- The homepage mixed site chrome and every section. It now composes a `SiteShell`, `Hero`, `SelectedWork`, and `About`. The shell uses small `SiteHeader` and `SiteFooter` components. MDX stays in About; no client component or generic section framework was introduced.
- Selected Work previously counted published entries but always rendered the empty state. It now filters drafts, orders featured records first (stable within each group), and renders a semantic list of ProjectCards when nonempty. Empty and draft-only collections share the honest empty state.
- Primitive palette values now feed semantic aliases for page surface, primary/secondary/accent text, borders, selection, and focus. Tailwind's named colors reuse these aliases. Container width/gutters and grid columns/gaps are shared layout tokens.
- Responsive rules explicitly cover mobile (4 columns, <768px), tablet (8 columns, 768–1023px), and desktop (12 columns, >=1024px). Content uses min-width: 0; navigation targets have 44px height.
- A visually garbled hero arrow was replaced with an HTML character reference.
- Node 24.18.0 is pinned in both version-manager files and package engines, with matching Node 24 type definitions. GitHub Actions reads `.nvmrc` and installs from the lockfile.
- `AGENTS.md` was generated by the installed Next.js dev server; its framework documentation guidance is retained.

## Project content contract

`publicationStatus` is draft or published; `developmentStatus` is independently in-progress, completed, or archived. Publishing an in-progress record never labels it completed. `featured` controls ordering, not publication.

Links include an HTTPS URL, kind, label, and owner-reviewed `verifiedOn` date. These fields record a manual verification assertion, not automated proof: confirm each destination and date before publishing. Types constrain authoring but do not validate external input; all current content is trusted local repository content.

Optional covers use local public asset paths, descriptive alt text (empty only for decorative images), and actual width/height. Next Image uses `unoptimized` to preserve static-export compatibility. Confirm the asset exists before publication. Optional `caseStudy.contentPath` references an authored MDX file only; cards intentionally generate no case study route until a later approved sprint implements routing. Do not fill a case study reference before its content exists.

The real project collection remains empty. Synthetic fixtures exist only in tests and are never imported by the site.

## Dependency audit decision

The full audit reports **8 moderate findings**, all propagated from one development dependency: `@typescript-eslint/typescript-estree` -> `minimatch@10.2.6`. Production audit reports **0 vulnerabilities**.

Source: [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249). The advisory describes attacker-controlled glob amplification at optimizationLevel >= 2; patched version is 11.0.1. Registry inspection on the review date shows the latest typescript-estree (8.72.1) still requests minimatch ^10.2.2.

Decision: temporarily accept this development-only exposure. The app does not accept glob patterns, ship ESLint to visitors, or execute a runtime server. CI lints repository content, so deliberately malicious contributor code remains an exposure; workflow permissions are read-only, with no deployment or secrets configured. This is a reduced exposure assessment, not a claim that development dependencies are harmless.

Do not use `npm audit fix --force`: the suggested eslint-config-next 15.5.29 downgrade mismatches Next 16. Do not force minimatch 11 over its consumer's declared major range without compatibility review. Revisit when typescript-eslint ships a compatible patch and before accepting untrusted contributions. Production audit is blocking at moderate severity; full audit is separately visible and nonblocking. Any new advisory requires fresh review. ESLint 9 also emits an upstream support deprecation warning; keep alignment with the Next lint preset under review rather than upgrade its major independently.
